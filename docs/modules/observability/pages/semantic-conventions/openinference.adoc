= OpenInference Semantic Conventions
:page-aliases: observation:semantic-conventions/openinference.adoc, observability:generative-ai.adoc, observability:ai.adoc

Spring AI provides built-in instrumentation for models, tools, and agentic workflows based on the Micrometer APIs. Arconia lets you configure your Spring AI applications to export telemetry data adopting the https://arize-ai.github.io/openinference/spec/[OpenInference Semantic Conventions] instead of the default Micrometer conventions, enabling rich trace visualization in platforms like https://arize.com/docs/phoenix[Arize Phoenix] and https://arize.com/products/ax/[Arize AX].

Arconia provides a Phoenix Dev Service you can use during development and testing. Check out the xref:dev-services:phoenix.adoc[Phoenix Dev Service] documentation for more details.

[NOTE]
====
Arize AX provides a managed path for tracing, monitoring, and evaluating Arconia-based Spring AI applications. Check out the Arize AX documentation for the https://arize.com/docs/ax/integrations/java/arconia/arconia-tracing[Arconia integration] for more details.
====

[WARNING]
====
The https://arize-ai.github.io/openinference/spec/[OpenInference Semantic Conventions] are still experimental, and they might change in the future.
====

== Getting Started

Add the Arconia OpenInference AI Semantic Conventions dependency to your project.

[tabs]
======
Gradle::
+
[source,groovy]
----
dependencies {
  implementation 'io.arconia:arconia-openinference-ai-semantic-conventions'
}
----

Maven::
+
[source,xml]
----
<dependency>
    <groupId>io.arconia</groupId>
    <artifactId>arconia-openinference-ai-semantic-conventions</artifactId>
</dependency>
----

=== Dev Service

During development and testing, you can use the xref:dev-services:phoenix.adoc[Phoenix Dev Service] to spin up a local Arize Phoenix instance automatically. Add the Dev Service dependency to your project:

[tabs]
======
Gradle::
+
[source,groovy,subs="attributes"]
----
dependencies {
  testAndDevelopmentOnly "io.arconia:arconia-dev-services-phoenix"
}
----

Maven::
+
[source,xml,subs="attributes,verbatim"]
----
<dependency>
    <groupId>io.arconia</groupId>
    <artifactId>arconia-dev-services-phoenix</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>
</dependency>
----
======

When the Dev Service is active, Arconia configures OpenTelemetry automatically to export traces to Phoenix based on the OpenInference Semantic Conventions. No additional OTLP configuration is needed for local development.

=== Arize Phoenix

To send telemetry to a hosted Arize Phoenix instance, configure the OTLP exporter with your endpoint:

[source,properties]
----
arconia.otel.exporter.otlp.endpoint=https://<your-phoenix-endpoint>
arconia.otel.exporter.otlp.headers=Authorization=Bearer ${PHOENIX_API_KEY}
----

Alternatively, you can use the standard OpenTelemetry environment variables:

[source,env]
----
OTEL_EXPORTER_OTLP_ENDPOINT=https://<your-phoenix-endpoint>
OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer <your-phoenix-api-key>"
----

You can also set the project name to control how traces are grouped in Phoenix:

[source,properties]
----
arconia.observations.conventions.openinference.ai.project-name=my-app
----

The project name is the `openinference.project.name` resource attribute, which Arconia contributes through the xref:opentelemetry:resource.adoc[resource support] of the Arconia OpenTelemetry Spring Boot Starter, using the service name when the property is not set. With the Spring Boot OpenTelemetry support, set the resource attribute directly instead, otherwise Phoenix files the traces under its `default` project:

[source,properties]
----
management.opentelemetry.resource-attributes.openinference.project.name=my-app
----

== Features

The module records OpenInference spans for:

* Chat model calls, with the model, the parameters, the available tools, the input and output messages, and the token usage.
* Embedding model calls, with the model and the input texts. Vectors are recorded as their dimension count, not their values.
* Tool executions, with the arguments and the result.
* Chat client calls, recorded as agents and grouped into sessions by the conversation ID of the chat memory.
* Advisors, recorded as chains or guardrails.

Content is captured by default, following the OpenInference specification. Use the `hide-*` properties below to leave out what must not be recorded.

include::partial$content-capturing-warning.adoc[]

The `hide-*` properties follow the OpenInference configuration. They also hide any other attribute carrying the same content, such as `input.value` when hiding the input messages, so Arconia sometimes hides more than the reference instrumentations.

== Configuration Properties

You can configure the OpenInference Semantic Conventions via configuration properties.

.OpenInference Configuration Properties
|===
|Property |Default |Description

| `arconia.observations.conventions.openinference.ai.enabled`
| `true`
| Whether to enable the OpenInference AI Semantic Conventions module.

| `arconia.observations.conventions.openinference.ai.project-name`
| -
| Name of the project in the OpenInference backend where to send the telemetry data. If not set, the `service.name` resource attribute is used.

| `arconia.observations.conventions.openinference.ai.base64-image-max-length`
| `32000`
| Maximum length of a base64-encoded media in the messages, such as an image or a document. Longer media are redacted.

| `arconia.observations.conventions.openinference.ai.hide-embeddings-text`
| `false`
| Whether to hide all embedding text.

| `arconia.observations.conventions.openinference.ai.hide-embeddings-vectors`
| `false`
| Whether to hide the dimension summary recorded in place of embedding vectors, which are never recorded.

| `arconia.observations.conventions.openinference.ai.hide-llm-invocation-parameters`
| `false`
| Whether to hide the LLM invocation parameters.

| `arconia.observations.conventions.openinference.ai.hide-llm-tools`
| `false`
| Whether to hide the definitions of the tools available to the model. They are also hidden when hiding all inputs.

| `arconia.observations.conventions.openinference.ai.hide-inputs`
| `false`
| Whether to hide all inputs, including the input messages, the tool definitions, and the embedding text.

| `arconia.observations.conventions.openinference.ai.hide-input-images`
| `false`
| Whether to hide all images from the input messages.

| `arconia.observations.conventions.openinference.ai.hide-input-messages`
| `false`
| Whether to hide all input messages.

| `arconia.observations.conventions.openinference.ai.hide-input-text`
| `false`
| Whether to hide all texts from the input messages.

| `arconia.observations.conventions.openinference.ai.hide-outputs`
| `false`
| Whether to hide all outputs, including the output messages and the embedding vector summary.

| `arconia.observations.conventions.openinference.ai.hide-output-text`
| `false`
| Whether to hide all texts from the output messages.

| `arconia.observations.conventions.openinference.ai.hide-output-messages`
| `false`
| Whether to hide all output messages.
|===
