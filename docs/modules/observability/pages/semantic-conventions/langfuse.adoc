= Langfuse Semantic Conventions

:flavor-value: langfuse
:flavor-default-capture-message-content: true
:flavor-default-capture-tool-definitions: true
:flavor-default-capture-tool-call-content: true

Spring AI provides built-in instrumentation for models, tools, and workflows based on the Micrometer APIs. Arconia lets you configure your Spring AI applications to export traces that https://langfuse.com[Langfuse] turns into its observations: generations, embeddings, tool calls, agents, and chains, with their inputs, outputs, token usage, and costs.

Langfuse ingests the https://opentelemetry.io/docs/specs/semconv/gen-ai/[OpenTelemetry Semantic Conventions for Generative AI], so the `langfuse` flavor builds on the xref:semantic-conventions/opentelemetry.adoc#_generative_ai[OpenTelemetry flavor] and only adds what Langfuse needs on top of it.

Arconia provides a Langfuse Dev Service you can use during development and testing. Check out the xref:dev-services:langfuse.adoc[Langfuse Dev Service] documentation for more details.

[WARNING]
====
The https://opentelemetry.io/docs/specs/semconv/gen-ai/[OpenTelemetry Semantic Conventions for Generative AI] are still experimental, and they might change in the future.
====

=== Dev Service

During development and testing, you can use the xref:dev-services:langfuse.adoc[Langfuse Dev Service] to spin up a local Langfuse instance automatically. Add the Dev Service dependency to your project:

[tabs]
======
Gradle::
+
[source,groovy,subs="attributes"]
----
dependencies {
  testAndDevelopmentOnly "io.arconia:arconia-dev-services-langfuse"
}
----

Maven::
+
[source,xml,subs="attributes,verbatim"]
----
<dependency>
    <groupId>io.arconia</groupId>
    <artifactId>arconia-dev-services-langfuse</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>
</dependency>
----
======

When the Dev Service is active, Arconia configures OpenTelemetry automatically to send the traces to Langfuse, authenticated with the API keys of the Langfuse project. No additional OTLP configuration is needed for local development.

=== Langfuse Cloud

To send traces to https://langfuse.com[Langfuse Cloud] or to your own Langfuse deployment, configure the OTLP exporter with the endpoint of your Langfuse instance and the API keys of your project, encoded as `base64(<public-key>:<secret-key>)` in a `LANGFUSE_AUTH` environment variable:

[source,properties]
----
arconia.otel.exporter.otlp.endpoint=https://cloud.langfuse.com/api/public/otel
arconia.otel.exporter.otlp.headers[Authorization]=Basic ${LANGFUSE_AUTH}
arconia.otel.exporter.otlp.headers[x-langfuse-ingestion-version]=4
----

For the US region of Langfuse Cloud, use `https://us.cloud.langfuse.com/api/public/otel` as the endpoint. Langfuse requires the `x-langfuse-ingestion-version` header from OpenTelemetry exporters.

Alternatively, you can use the standard OpenTelemetry environment variables:

[source,env]
----
OTEL_EXPORTER_OTLP_ENDPOINT=https://cloud.langfuse.com/api/public/otel
OTEL_EXPORTER_OTLP_HEADERS="Authorization=Basic <base64-encoded-api-keys>,x-langfuse-ingestion-version=4"
----

Since Langfuse supports only traces via OTLP with the HTTP/Protobuf protocol, you might want to disable the export of logs and metrics:

[source,properties]
----
arconia.otel.logs.exporter.type=none
arconia.otel.metrics.exporter.type=none
----

== Features

The `langfuse` flavor records the same attributes as the xref:semantic-conventions/opentelemetry.adoc#_generative_ai[OpenTelemetry flavor], which Langfuse maps to its observations:

* Chat model calls become generations, with the model, its parameters, the token usage, and the input and output messages. Langfuse computes their costs from the model and the token usage.
* Embedding model calls become embeddings, and image model calls become generations.
* Tool executions become tool calls, with their arguments and result.
* Chat client calls become agents, grouped into a Langfuse session by the conversation ID of the chat memory, recorded as `gen_ai.conversation.id` on the agent span and on the spans nested in it.
* Advisors become chains, through the `langfuse.observation.type` attribute, since Langfuse doesn't derive the chain type from the OpenTelemetry Semantic Conventions.

The input and output messages are always recorded as span attributes, since Langfuse accepts traces only.

Content capturing is enabled by default, matching the behavior of the official Langfuse SDKs.
