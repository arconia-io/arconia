Spring AI provides built-in instrumentation for models, vector stores, and workflows based on the Micrometer APIs. Arconia lets you configure your Spring AI applications to export telemetry data adopting the https://traceloop.com/docs/openllmetry[OpenLLMetry Semantic Conventions] instead of the default Micrometer conventions, enabling rich trace visualization in platforms like https://www.traceloop.com[Traceloop].

[WARNING]
====
The https://traceloop.com/docs/openllmetry[OpenLLMetry Semantic Conventions] are still experimental, and they might change in the future.
====

=== Traceloop

Configure the OTLP exporter to send traces to https://www.traceloop.com[Traceloop], making sure you defined your Traceloop API Key in a `TRACELOOP_API_KEY` environment variable:

[source,properties]
----
arconia.otel.exporter.otlp.endpoint=https://api.traceloop.com
arconia.otel.exporter.otlp.headers=Authorization=Bearer ${TRACELOOP_API_KEY}
----

Alternatively, you can use the standard OpenTelemetry environment variables:

[source,env]
----
OTEL_EXPORTER_OTLP_ENDPOINT=https://api.traceloop.com
OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer <your-traceloop-api-key>"
----

== Features

The module provides OpenLLMetry-compatible semantic conventions for the following observation types:

* Chat model, embedding model, and image model spans following the OpenTelemetry Semantic Conventions for Generative AI, as the current OpenLLMetry instrumentations do.
* Tool execution spans with input/output content.
* Advisor spans, recorded as Traceloop tasks.
* Chat client spans with input/output content. The conversation ID of the chat memory is recorded as `gen_ai.conversation.id` and as the `session_id` association property (`traceloop.association.properties.session_id`), on the chat client span and on the spans nested in it.
* Token usage for inference operations, including the total and the cached input tokens.
* Input/output message content, captured as span attributes.

Content capturing is enabled by default, matching the behavior of the official OpenLLMetry SDKs. Set the `capture-*` properties below to `false` to turn it off.

include::partial$content-capturing-warning.adoc[]

Model calls, embeddings, tool executions, and chat client calls ending in an error get the `error.type` attribute when the xref:semantic-conventions/opentelemetry.adoc#_errors[error conventions] of the Arconia OpenTelemetry Semantic Conventions module are also on the classpath.
