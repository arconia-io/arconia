Spring AI provides built-in instrumentation for models, tools, and agentic workflows based on the Micrometer APIs. Arconia lets you configure your Spring AI applications to export telemetry data adopting the https://docs.langchain.com/langsmith/trace-with-opentelemetry[LangSmith Semantic Conventions] instead of the default Micrometer conventions, enabling rich trace visualization in the https://www.langchain.com/langsmith[LangSmith] platform.

[WARNING]
====
The https://docs.langchain.com/langsmith/trace-with-opentelemetry[LangSmith Semantic Conventions] are still experimental, and they might change in the future.
====

Set the convention flavor to `langsmith`:

[tabs]
======
YAML::
+
[source,yaml]
----
arconia:
  observations:
    conventions:
      opentelemetry:
        ai:
          flavor: langsmith
----

Properties::
+
[source,properties]
----
arconia.observations.conventions.opentelemetry.ai.flavor=langsmith
----

=== LangSmith

Configure the OTLP exporter to send traces to LangSmith, making sure you defined your LangSmith API Key in a `LANGSMITH_API_KEY` environment variable:

[tabs]
======
YAML::
+
[source,yaml]
----
arconia:
  otel:
    exporter:
      otlp:
        endpoint: https://eu.api.smith.langchain.com/otel
        headers:
          x-api-key: ${LANGSMITH_API_KEY}
          Langsmith-Project: my-project
----

Properties::
+
[source,properties]
----
arconia.otel.exporter.otlp.endpoint=https://eu.api.smith.langchain.com/otel
arconia.otel.exporter.otlp.headers[x-api-key]=${LANGSMITH_API_KEY}
arconia.otel.exporter.otlp.headers[Langsmith-Project]=my-project
----
======

For US-hosted LangSmith, use `https://api.smith.langchain.com/otel` as the endpoint. The `Langsmith-Project` header selects the LangSmith project receiving the traces, which is `default` when the header is not set.

Alternatively, you can use the standard OpenTelemetry Environment Variables:

[source,env]
----
OTEL_EXPORTER_OTLP_ENDPOINT=https://eu.api.smith.langchain.com/otel
OTEL_EXPORTER_OTLP_HEADERS="x-api-key=<your-langsmith-api-key>,Langsmith-Project=my-project"
----

== Features

The `langsmith` flavor records Spring AI observations for LangSmith:

* Chat model calls, with the model, the parameters, and the token usage, including the cached input tokens.
* Embedding and image model calls.
* Tool executions, with their arguments and result.
* Chat client calls, grouped into a LangSmith thread by the conversation ID of the chat memory.
* Advisors, recorded as chains.
* The input and output messages, recorded the way the LangSmith SDKs do.

Content capturing is enabled by default, matching the behavior of the official LangSmith SDKs. Set the `capture-*` properties below to `false` to turn it off.

include::partial$content-capturing-warning.adoc[]

Model calls, embeddings, tool executions, and chat client calls ending in an error get the `error.type` attribute when the xref:semantic-conventions/opentelemetry.adoc#_errors[error conventions] of the Arconia OpenTelemetry Semantic Conventions module are also on the classpath.
