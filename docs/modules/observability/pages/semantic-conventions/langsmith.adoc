Spring AI provides built-in instrumentation for models and workflows based on the Micrometer APIs. Arconia lets you configure your Spring AI applications to export telemetry data adopting the https://docs.langchain.com/langsmith/trace-with-opentelemetry[LangSmith Semantic Conventions] instead of the default Micrometer conventions, enabling rich trace visualization in the https://www.langchain.com/langsmith[LangSmith] platform.

[WARNING]
====
The https://docs.langchain.com/langsmith/trace-with-opentelemetry[LangSmith Semantic Conventions] are still experimental, and they might change in the future.
====

== Getting Started

Add the Arconia OpenTelemetry AI Semantic Conventions dependency to your project. The module auto-activates when present on the classpath.

include::partial$opentelemetry-ai-dependency.adoc[]

include::partial$ai-conventions-activation.adoc[]

Set the convention flavor to `langsmith`:

[source,properties]
----
arconia.observations.conventions.opentelemetry.ai.flavor=langsmith
----

include::partial$opentelemetry-setup.adoc[]

Configure the OTLP exporter to send traces to LangSmith, making sure you defined your LangSmith API Key in a `LANGSMITH_API_KEY` environment variable:

[source,properties]
----
arconia.otel.exporter.otlp.endpoint=https://eu.api.smith.langchain.com/otel
arconia.otel.exporter.otlp.headers[x-api-key]=${LANGSMITH_API_KEY}
arconia.otel.exporter.otlp.headers[Langsmith-Project]=my-project
----

For US-hosted LangSmith, use `https://api.smith.langchain.com/otel` as the endpoint. The `Langsmith-Project` header selects the LangSmith project receiving the traces, which is `default` when the header is not set.

Alternatively, you can use the standard OpenTelemetry Environment Variables:

[source,env]
----
OTEL_EXPORTER_OTLP_ENDPOINT=https://eu.api.smith.langchain.com/otel
OTEL_EXPORTER_OTLP_HEADERS="x-api-key=<your-langsmith-api-key>,Langsmith-Project=my-project"
----

Since LangSmith supports only traces, you might want to disable the export of logs and metrics:

[source,properties]
----
arconia.otel.logs.exporter.type=none
arconia.otel.metrics.exporter.type=none
----

== Features

The module provides semantic conventions for the following observation types:

* Chat model spans with full parameter tracking (temperature, max tokens, penalties, stop sequences, etc.).
* Embedding model spans.
* Tool execution spans with input/output content.
* Image model spans.
* Chat client spans with input/output content. The conversation ID of the chat memory is recorded as the `thread_id` metadata, so LangSmith groups the traces of a conversation into a thread.
* Token usage for inference operations, including cached input tokens.
* Input/output message content, captured as the `gen_ai.prompt` and `gen_ai.completion` span attributes, the way the LangSmith SDKs record the inputs and outputs of a run.

Content capturing is enabled by default, matching the behavior of the official LangSmith SDKs.
