= OpenLIT Dev Service
:service-name: openlit

A service providing https://openlit.io[OpenLIT], an AI Observability and Evaluation platform based on OpenTelemetry, for development and testing purposes. It consists of:

* https://openlit.io[OpenLIT] for visualizing and exploring telemetry data from AI applications.
* https://clickhouse.com[ClickHouse] as the backend database for storing telemetry data.

It works with Spring Boot libraries that support OpenTelemetry, including:

* xref:opentelemetry:index.adoc[Arconia OpenTelemetry].

[NOTE]
====
This Dev Service is mutually exclusive with other OpenTelemetry dev services. If more than one is active at the same time, the application will fail at startup with a clear error message. Disable all but one by setting `arconia.dev.services.<name>.enabled=false`.
====

In test mode, the Dev Service is skipped by default, since most tests have no use for a telemetry backend. For the tests that verify the telemetry the application exports, set `arconia.dev.services.{service-name}.skip-in-tests` to `false`, preferably in a configuration shared by those tests, such as an `application-test.yml` file, so that they share one application context and one container (see xref:index.adoc#_dev_services_in_test_mode[Dev Services in Test Mode]).

By default, when running the application in dev mode, multiple applications running simultaneously use the same OpenLIT Dev Service: the application connects to a running OpenLIT Dev Service started by another application if available, or else starts its own that other applications can discover in turn. To always start a container for the application alone, set the `arconia.dev.services.{service-name}.reuse-strategy` property to `none`. Learn more about xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

== Accessing OpenLIT

The application logs will show you the URL where you can access the OpenLIT UI.

[source,logs]
----
...i.a.d.s.startup  : Dev Service 'openlit' is ready in container <container-id> (ghcr.io/openlit/openlit, localhost:<port>, reuse-strategy: framework)
...i.a.d.s.startup  : Dev Service 'openlit' links: OpenLIT UI: http://localhost:<port>
----

The service is pre-configured with a demo account which is automatically authenticated when accessing OpenLIT the first time. The credentials are: `user@openlit.io` (username) and `openlituser` (password).

OpenLIT restricts a few operations for the demo account, such as changing the database configuration and deleting API keys or prompts. If you need them, disable the automatic sign-in by setting the `DEMO_ACCOUNT_EMAIL` environment variable to an empty value, and sign in with the same credentials from the OpenLIT login page: the restrictions only apply while the account is configured as the demo account.

[source,yaml]
----
arconia:
  dev:
    services:
      openlit:
        environment:
          DEMO_ACCOUNT_EMAIL: ""
----

By default, logs, metrics, and traces are exported via OTLP using the HTTP/Protobuf format.

== Configuring the Dev Service

You can configure the Dev Service via configuration properties.

|===
|Property |Default |Description

| `arconia.dev.services.{service-name}.enabled`
| `true`
| Whether the dev service is enabled.

| `arconia.dev.services.{service-name}.image-name`
| `ghcr.io/openlit/openlit`
| Full name of the container image used in the dev service.

| `arconia.dev.services.{service-name}.environment`
| `{}`
| Environment variables to set in the service.

| `arconia.dev.services.{service-name}.network-aliases`
| `[]`
| Additional hostnames the dev service container is reachable by on the shared network, next to the name of the dev service. Only applicable when the shared network is enabled.

| `arconia.dev.services.{service-name}.port`
| `0`
| Fixed port for exposing the OpenLIT UI port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.resources`
| `[]`
| Resources from the classpath or host filesystem to copy into the container. They can be files or directories that will be copied to the specified destination path inside the container at startup and are immutable (read-only).

| `arconia.dev.services.{service-name}.reuse-strategy`
| `framework`
| Strategy for reusing a running container for the dev service across applications or restarts. Only applicable in dev mode. See xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

| `arconia.dev.services.{service-name}.startup-timeout`
| `120s`
| Maximum waiting time for the service to start, counted from the container start.

| `arconia.dev.services.{service-name}.volumes`
| `[]`
| Files or directories to mount from the host filesystem into the container. They are mounted at the specified destination path inside the container at startup and are mutable (read-write). Changes in either the host or the container will be immediately reflected in the other.

| `arconia.dev.services.{service-name}.clickhouse-image-name`
| `clickhouse/clickhouse-server`
| Full name of the container image used for the internal ClickHouse instance.

| `arconia.dev.services.{service-name}.skip-in-tests`
| `true`
| Whether the dev service is skipped in test mode, where the application rarely needs a telemetry backend. Set it to false for tests that verify the telemetry the application exports.

| `arconia.dev.services.{service-name}.otlp-grpc-port`
| `0`
| Fixed port for exposing the OTLP gRPC port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.otlp-http-port`
| `0`
| Fixed port for exposing the OTLP HTTP port to the host. When it's 0 (default), a random available port is assigned dynamically.
|===
