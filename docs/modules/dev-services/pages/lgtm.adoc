= Grafana LGTM Dev Service
:service-name: lgtm

A service providing a Grafana LGTM observability platform based on OpenTelemetry for development and testing purposes. It consists of:

* https://grafana.com/oss/grafana[Grafana] for visualizing and exploring telemetry data.
* https://opentelemetry.io/docs/collector[OpenTelemetry Collector] for collecting telemetry data from your application using OTLP.
* https://grafana.com/oss/loki[Grafana Loki] for storing and querying logs.
* https://prometheus.io[Prometheus] for storing and querying metrics.
* https://grafana.com/oss/tempo[Grafana Tempo] for storing and querying traces.

It works with Spring Boot libraries that support OpenTelemetry, including:

* xref:opentelemetry:index.adoc[Arconia OpenTelemetry].

[NOTE]
====
This Dev Service is mutually exclusive with other OpenTelemetry dev services. If more than one is active at the same time, the application will fail at startup with a clear error message. Disable all but one by setting `arconia.dev.services.<name>.enabled=false`.
====

== Running the Application

By default, when running the application in dev mode, multiple applications running simultaneously use the same Grafana LGTM Dev Service: the application connects to a running Grafana LGTM Dev Service started by another application if available, or else starts its own that other applications can discover in turn. To always start a container for the application alone, set the `arconia.dev.services.{service-name}.reuse-strategy` property to `none`. Learn more about xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

== Accessing Grafana

The application logs will show you the URL where you can access the Grafana UI.

[source,logs]
----
...i.a.d.s.startup  : Dev Service 'lgtm' is ready in container <container-id> (grafana/otel-lgtm, reuse-strategy: framework)
...i.a.d.s.startup  : Dev Service 'lgtm' links: Grafana: http://localhost:<port>, OTLP/HTTP: http://localhost:<port>, OTLP/gRPC: http://localhost:<port>
----

By default, logs, metrics, and traces are exported via OTLP using the HTTP/Protobuf format.

== Grafana Dashboards

The Dev Service provisions Grafana with dashboards for Spring Boot applications, replacing the ones bundled with the `grafana/otel-lgtm` image. The dashboards are picked for the application:

|===
|Dashboard |Provisioned

| JVM Metrics (Micrometer)
| When the JVM metrics follow the Micrometer conventions, the Spring Boot default.

| JVM Metrics (OpenTelemetry)
| When the JVM metrics follow the OpenTelemetry semantic conventions, that is when the xref:observability:semantic-conventions/opentelemetry.adoc[Arconia OpenTelemetry Semantic Conventions] module is on the classpath and its JVM conventions are enabled.
|===

=== Contributing Dashboards

Any Grafana dashboard JSON file under `META-INF/grafana/dashboards` on the classpath is provisioned as well, with no configuration needed. Place your own dashboards in the `src/main/resources/META-INF/grafana/dashboards` directory of your application.

[source,text]
----
src/main/resources
└── META-INF
    └── grafana
        └── dashboards
            ├── orders.json
            └── payments.json
----

A library can ship dashboards the same way, and they are provisioned whenever the library is on the classpath of the application. Each dashboard file needs a unique name: when two files share a name, the first one found is provisioned and the other is ignored with a warning in the logs.

Set `arconia.dev.services.{service-name}.dashboards.built-in.enabled` to `false` to provision only the contributed dashboards, or `arconia.dev.services.{service-name}.dashboards.enabled` to `false` to keep the dashboards bundled with the image.

To open one of the provisioned dashboards as the Grafana home page, set `arconia.dev.services.{service-name}.dashboards.home` to its file name.

[source,yaml]
----
arconia:
  dev:
    services:
      lgtm:
        dashboards:
          home: orders.json
----

NOTE: The dashboards are copied into the container when it starts. When the container is reused across application restarts (see `reuse-strategy`), changes to a dashboard file take effect the next time the container is started. When the application connects to a Grafana LGTM Dev Service started by another application, the dashboards are the ones provisioned by that application.

== Configuring the Dev Service

You can configure the Dev Service via configuration properties.

|===
|Property |Default |Description

| `arconia.dev.services.{service-name}.enabled`
| `true`
| Whether the dev service is enabled.

| `arconia.dev.services.{service-name}.image-name`
| `grafana/otel-lgtm`
| Full name of the container image used in the dev service.

| `arconia.dev.services.{service-name}.environment`
| `{}`
| Environment variables to set in the service.

| `arconia.dev.services.{service-name}.network-aliases`
| `[]`
| Additional hostnames the dev service container is reachable by on the shared network, next to the name of the dev service. Only applicable when the shared network is enabled.

| `arconia.dev.services.{service-name}.port`
| `0`
| Fixed port for exposing the Grafana port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.resources`
| `[]`
| Resources from the classpath or host filesystem to copy into the container. They can be files or directories that will be copied to the specified destination path inside the container at startup and are immutable (read-only).

| `arconia.dev.services.{service-name}.reuse-strategy`
| `framework`
| Strategy for reusing a running container for the dev service instead of starting a new one. With `framework`, the dev service is discoverable by other applications, and the application connects to an existing dev service if available. With `testcontainers`, the container is kept running across application restarts, relying on the Testcontainers reusable containers feature, which must be enabled in the `~/.testcontainers.properties` file; such containers are not stopped automatically and must be cleaned up manually. Only applicable in dev mode.

| `arconia.dev.services.{service-name}.startup-timeout`
| `120s`
| Maximum waiting time for the service to start, counted from the container start.

| `arconia.dev.services.{service-name}.volumes`
| `[]`
| Files or directories to mount from the host filesystem into the container. They are mounted at the specified destination path inside the container at startup and are mutable (read-write). Changes in either the host or the container will be immediately reflected in the other.

| `arconia.dev.services.{service-name}.otlp-grpc-port`
| `0`
| Fixed port for exposing the OTLP gRPC port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.otlp-http-port`
| `0`
| Fixed port for exposing the OTLP HTTP port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.loki-port`
| `0`
| Fixed port for exposing the Loki port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.tempo-port`
| `0`
| Fixed port for exposing the Tempo port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.prometheus-port`
| `0`
| Fixed port for exposing the Prometheus port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.dashboards.enabled`
| `true`
| Whether the dev service provisions Grafana dashboards. When disabled, Grafana keeps the dashboards bundled with the container image.

| `arconia.dev.services.{service-name}.dashboards.home`
|
| File name of the provisioned dashboard to open as the Grafana home page, for example, `orders.json`. By default, Grafana opens its own home page.

| `arconia.dev.services.{service-name}.dashboards.built-in.enabled`
| `true`
| Whether the dashboards shipped with the dev service are provisioned, next to the ones contributed by the classpath.
|===
