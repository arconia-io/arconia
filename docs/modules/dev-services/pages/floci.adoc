= Floci Dev Service
:service-name: floci

A service providing https://floci.io[Floci], a free open-source local AWS emulator, for development and testing purposes.

It works with Spring Boot libraries that support AWS, including:

* https://awspring.io[Spring Cloud AWS]

The Dev Service brings the core of https://awspring.io[Spring Cloud AWS] with it, including its support for connecting to Floci. Add the Spring Cloud AWS starter of each AWS service your application uses, such as `io.awspring.cloud:spring-cloud-aws-starter-s3`: the AWS endpoint, region, and credentials of its clients are configured automatically.

[NOTE]
====
Floci exposes a single HTTP endpoint for all emulated AWS services. When using Spring Cloud AWS S3, path-style access is enabled while the Floci Dev Service module is on the classpath, also when the application connects to an endpoint of its own instead of the Dev Service.
====

[NOTE]
====
This Dev Service is mutually exclusive with other AWS dev services. If more than one is active at the same time, the application will fail at startup with a clear error message. Disable all but one by setting `arconia.dev.services.<name>.enabled=false`.
====

== Running the Application

include::partial$running-application.adoc[]

By default, each application starts its own Floci Dev Service. To let multiple applications running simultaneously in dev mode use the same one, set the `arconia.dev.services.{service-name}.reuse-strategy` property to `framework`: the application connects to a running Floci Dev Service started by another application if available, or else starts its own that other applications can discover in turn. The applications using the same Dev Service must use the same region. Learn more about xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

== Configuring the Dev Service

You can configure the Dev Service via configuration properties.

|===
|Property |Default |Description

| `arconia.dev.services.{service-name}.enabled`
| `true`
| Whether the dev service is enabled.

| `arconia.dev.services.{service-name}.image-name`
| `floci/floci`
| Full name of the container image used in the dev service.

| `arconia.dev.services.{service-name}.environment`
| `{}`
| Environment variables to set in the service.

| `arconia.dev.services.{service-name}.network-aliases`
| `[]`
| Additional hostnames the dev service container is reachable by on the shared network, next to the name of the dev service. Only applicable when the shared network is enabled.

| `arconia.dev.services.{service-name}.port`
| `0`
| Fixed port for exposing the Floci port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.resources`
| `[]`
| Resources from the classpath or host filesystem to copy into the container. They can be files or directories that will be copied to the specified destination path inside the container at startup and are immutable (read-only).

| `arconia.dev.services.{service-name}.reuse-strategy`
| `none`
| Strategy for reusing a running container for the dev service across applications or restarts. Only applicable in dev mode. See xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

| `arconia.dev.services.{service-name}.startup-timeout`
| `30s`
| Maximum waiting time for the service to start, counted from the container start.

| `arconia.dev.services.{service-name}.volumes`
| `[]`
| Files or directories to mount from the host filesystem into the container. They are mounted at the specified destination path inside the container at startup and are mutable (read-write). Changes in either the host or the container will be immediately reflected in the other.
|===
