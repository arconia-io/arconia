= Light LDAP (LLDAP) Dev Service
:service-name: lldap

A service providing an https://ldap.com[LDAP] instance for development and testing purposes. It's based on https://github.com/lldap/lldap[LLDAP], which is "a lightweight authentication server that provides an opinionated, simplified LDAP interface for authentication".

It works with Spring Boot libraries that support LDAP, including:

* https://spring.io/projects/spring-data-ldap[Spring Data LDAP]

== Running the Application

include::partial$running-application.adoc[]

By default, each application starts its own LLDAP Dev Service. To let multiple applications running simultaneously in dev mode use the same one, set the `arconia.dev.services.{service-name}.reuse-strategy` property to `framework`: the application connects to a running LLDAP Dev Service started by another application if available, or else starts its own that other applications can discover in turn. The applications using the same Dev Service must use the same base DN and password. Learn more about xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

== Accessing the Management Console

The application logs will show you the URL where you can access the LLDAP Management Console.

[source,logs]
----
...i.a.d.s.startup  : Dev Service 'lldap' is ready in container 7c2e1f9a3b5d (lldap/lldap, localhost:<port>, reuse-strategy: none)
...i.a.d.s.startup  : Dev Service 'lldap' links: LLDAP Console: http://localhost:<port>
----

You can log in with username `admin` and password `password`. The default base DN is `dc=example,dc=com`. The same credentials are used by the application to connect to the LDAP server.

== Configuring the Dev Service

You can configure the Dev Service via configuration properties.

|===
|Property |Default |Description

| `arconia.dev.services.{service-name}.enabled`
| `true`
| Whether the dev service is enabled.

| `arconia.dev.services.{service-name}.image-name`
| `lldap/lldap`
| Full name of the container image used in the dev service.

| `arconia.dev.services.{service-name}.environment`
| `{}`
| Environment variables to set in the service.

| `arconia.dev.services.{service-name}.network-aliases`
| `[]`
| Additional hostnames the dev service container is reachable by on the shared network, next to the name of the dev service. Only applicable when the shared network is enabled.

| `arconia.dev.services.{service-name}.port`
| `0`
| Fixed port for exposing the LDAP port to the host. When it's 0 (default), a random available port is assigned dynamically.

| `arconia.dev.services.{service-name}.resources`
| `[]`
| Resources from the classpath or host filesystem to copy into the container. They can be files or directories that will be copied to the specified destination path inside the container at startup and are immutable (read-only).

| `arconia.dev.services.{service-name}.reuse-strategy`
| `none`
| Strategy for reusing a running container for the dev service across applications or restarts. Only applicable in dev mode. See xref:index.adoc#_reusing_dev_services[Reusing Dev Services].

| `arconia.dev.services.{service-name}.startup-timeout`
| `30s`
| Maximum waiting time for the service to start, counted from the container start.

| `arconia.dev.services.{service-name}.volumes`
| `[]`
| Files or directories to mount from the host filesystem into the container. They are mounted at the specified destination path inside the container at startup and are mutable (read-write). Changes in either the host or the container will be immediately reflected in the other.

| `arconia.dev.services.{service-name}.management-console-port`
| `0`
| Fixed port for exposing the LLDAP Management Console to the host. When it's 0 (default), a random available port is assigned dynamically.
|===
